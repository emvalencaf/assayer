# Changelog

## [Unreleased]

### Fixed
- README no longer claims that results are pushed to LangSmith automatically: the `Runner` never calls `LangSmithPublisher`.

### Added
- `LangSmithAdapter` (#36, `assayer.integrations`): exports an Experiment to LangSmith. Cases are upserted as examples of a dataset (by name and `case_id`, never deleted), the Experiment is a project referencing that dataset, each Trajectory is a run tree with client UUIDs, `parent_run_id`, `trace_id` and `dotted_order` (kind mapped to `llm`/`tool`/`retriever`/`chain`, tokens and cost as `usage_metadata`), and each Score is feedback named `<metric>.<field>` with the Field in `extra`; Experiment-level Scores attach to the project. Credentials come from `LANGSMITH_API_KEY` with `LANGCHAIN_API_KEY` as fallback, or an injected `langsmith.Client`. It fixes the gaps of `LangSmithPublisher` listed in `docs/research/langsmith.md` and passes the shared conformance suite; an opt-in live smoke test needs credentials. `tests/` is now a package so suites can share `tests.adapters.conformance`.
- Adapter core (#35): `assayer.adapters` holds the sync `Adapter` Protocol (`name`, `export(experiment, *, include_content=True) -> ExportReport`, `close()`, context manager), `ExportReport` (`confirmed`, `queued`, `failed`, `skipped`, `notes`; `ok` means nothing failed or was skipped) and `ExportFailure` (`target_kind`, `target_id`, `kind`, `message`, `retryable`) with the closed taxonomy `auth | rate_limited | validation | transport | unsupported | unknown`. Ids of Cases, Trajectories, Steps and Scores are deterministic, so re-exporting an Experiment updates instead of duplicating. An item's failure is reported, never raised; an `auth` failure stops the export and lists the rest as `skipped`; direct calls are tried 3 times with exponential backoff, honoring `Retry-After` up to 60 s. `include_content=False` leaves out inputs, outputs, Step errors, Score comments, final output and state and Case references; Scores and Trajectories that cannot be linked to what they refer to are listed in `ExportReport.notes`, and an Experiment that cannot be planned is one `validation` failure of kind `experiment`. Local misconfiguration raises `AdapterConfigError`. `InMemoryAdapter` and the shared conformance suite (`tests/adapters/conformance.py`) set the bar for real Adapters; `Runner(adapter=...)` and `Runner.export(experiment, include_content=True)` are the export path.
- Judge-based and retrieval metrics (#34): `make_goal_success(judge)` scores 1 or 0 whether the agent achieved the goal, reference-free by default and reference-based when the Case has an `expected_outcome` (`metadata["reference"]` says which). `make_faithfulness(judge)` makes two Judge calls, one splitting `final_output` into claims and one checking each against the items of the `retrieval` Steps, and scores supported over total claims (counts and per-claim verdicts in `metadata`); no retrieved context or no claims is an `EvaluationFailure`. `make_context_precision(match)` (average precision of the ranking) and `make_context_recall(match)` compare the ranked `retrieval` Steps to `Case.reference_context_ids` (`match="id"`) or `Case.reference_contexts` (`match="string"`, case and whitespace insensitive; an item is relevant when its text holds a reference or is a snippet of one at least 20 characters long); a missing or empty reference, or a Trajectory without a retrieval Step, is an `EvaluationFailure`, not a 0. `register_retrieval_metrics(registry)` registers the four variants. `make_pass_hat_k(of=, threshold=0.5)` is the Experiment-level pass^k: the share of Cases whose k repetitions all score at least `threshold` for the metric `of`; a repetition that was not scored makes it an `EvaluationFailure`. To support these, `assayer.judges` gained `parse_claims` and `parse_claim_verdicts`.
- Judge core (#33): `assayer.judges` holds the sync `Judge` Protocol (`complete(messages, schema=None) -> JudgeResponse(text, usage?)`), `Prompt` (`id@version` and a SHA-256 `hash`) and tolerant parsing of the `{"score", "reason"}` reply (code fences and text around the JSON are ignored; `reason` is mandatory). `make_criteria_judge(judge, criteria=, evaluation_steps=, rubric=, level="trajectory"|"step", scale=(1, 5), prompt=)` (`assayer.metrics`) is the first Judge-based metric: the integer score is normalised to [0, 1] (`(0, 1)` is binary), the reason becomes the Score's `comment` and `prompt`/`prompt_hash` go in its `metadata`. An unparseable reply is asked for once more; a second one is an `EvaluationFailure`, never a 0. Judge calls (retries and failed attempts included) and tokens land in `Experiment.judge_calls` and `Experiment.judge_usage`, apart from the target's totals (also through `ListField`s). To support this, `Detailed` takes `comment` and `metadata`, and `MetricOutcome` carries `judge_usage` and `judge_calls`.
- Deterministic agent metrics (#32), registered by `register_agent_metrics(registry)`: `tool_correctness` (F1 over the multiset of tool names against `Case.expected_tool_calls`, each a name or a `{"name", "arguments"}` dictionary; `ordered=True` counts only names in the expected order), `tool_argument_match` (each expected call is paired with the earliest `tool` Step of the same name and scores the share of its expected argument leaves the Step's `input` holds with the same value; the Trajectory Score is the mean over the matched calls, with one Score per matched Step) and `end_state_match` (`Trajectory.final_state` against `Case.expected_state`, leaf by leaf at dotted paths with exact equality, as a Trajectory mean plus one Score per leaf; the expected state is a subset by default and `strict=True` scores extra paths 0). An `expected_state` with no `final_state` is an `EvaluationFailure`, and a Case without `expected_state` is skipped. To support this, a metric's function may return `Detailed(value, details)` to add finer-grained Scores to its own, or None to skip a subject without a Score or a failure; `Alignment` and `resolve` moved to `assayer.alignment` and `assayer.path` (still importable from `assayer.runner.field_map`).
- Schema utility and YAML/JSON field-map loading (#31): `schema_to_field_map(schema_or_pydantic_model)` drafts an editable field map (`FieldMapDraft.spec`, `.to_yaml()`, `.to_json()`) with default metrics per type: enum/boolean get `exact_match` and `f1`, a short string (`format`, `pattern` or `maxLength` of at most 64) `normalized_exact_match`, any other string `rouge_l`, a number `numeric_tolerance`, an array of non-objects `list_f1`, an object its properties at dotted paths and an array of objects a `best_match` list Field. Inside list items the corpus-level `f1` and `rouge_l` give way to trajectory-level metrics. An `id`/`key`-like property of an item is not scored and only yields a commented `# key: id` hint (when it is the item's only property the list aligns by that `key` instead, with no properties). A property whose schema is a union of several types, or a `$ref` that does not resolve, raises `ValueError` naming the property rather than being guessed at. `load_field_map(path)` reads `.json` or `.yaml`/`.yml` (YAML behind the new `assayer[yaml]` extra) and `parse_field_map(data, registry=None)` resolves plain data into a map for `Runner(field_metrics=...)`; a malformed map, or a file that cannot be read, raises `FieldMapError` (a `ValueError`) at load. New field-level metrics `exact_match`, `normalized_exact_match`, `numeric_tolerance` and `list_f1`, registered with `register_field_metrics(registry)`.
- Corpus metrics and consistency as Experiment-level metrics (#30): `register_corpus_metrics(registry)` registers BLEU, ROUGE-L, BERTScore, semantic similarity, accuracy, precision, recall, F1 and NER macro F1 as Experiment-level `Metric`s (`corpus_metric(name, fn)` lifts any `(predictions, references)` function), scoring the same as the legacy functions. `register_consistency_metrics(registry)` adds `agreement_rate`, `entropy`, `correct_rate`, `pass_at_k`, `recall_at_k` and `score_std` (`make_score_std(of="metric")` names the metric to measure) for a Runner with `repetitions=k`: each is measured per Case and the Score is the mean over Cases. `entropy` is the legacy value in bits divided by `log2(k)` (the most k repetitions allow), the one deliberate departure from parity, because a Score must fit [0, 1]. Experiment-level metrics also work in `field_metrics` (a Field's values only; they run after the whole-output metrics and the entries listed before them, so `score_std` must follow the metric it measures), but not inside the properties of a `ListField`. `Experiment.cases` keeps the Cases (with their ids) the Trajectories were produced for, and an Experiment-level metric's `requires` must hold for every Case. An Experiment-level metric with nothing to measure (no Trajectories) is an `EvaluationFailure`, never a 0, and `Runner.run`/`score` reject a Dataset whose Case ids repeat (an id given by position counts). No separate consistency pipeline is needed; the legacy one stays until the clean break.
- Alignment of list Fields (#29): `Runner(field_metrics={"items": ListField(properties={"name": [metric]}, align="best_match")})` pairs each predicted item with an expected one by `key`, `best_match` (default: greedy by descending similarity, threshold 0.5, ties by position) or `positional`, and scores the pairs property by property (mean over the pairs, at `items.name`). `list_precision`, `list_recall` and `list_f1` penalise missing and extra items, with the pairs and the unmatched indexes in their `metadata["alignment"]`; both empty scores 1.0, and nested `ListField`s align recursively.
- Per-Field measurement (#28): `Runner(field_metrics={"address.city": [metric, (metric, {"tolerance": 1})]})` scores each Field on its own, addressed by dotted path (a numeric segment indexes a list), with per-pair parameters passed to the metric's function. The metric sees the Field's value as `final_output` and the Case's as `expected_output`; its Scores and `EvaluationFailure`s carry the `field`, `Experiment.scores_by_field()` groups them, and a metric without a Field still scores the whole output. A malformed map is rejected when the Runner is built, before any target call; only trajectory-level metrics are accepted for now.
- `Runner.score(dataset, outputs)` scores collected outputs or Trajectories without calling the target, and `compare(a, b)` (`assayer.runner`) returns a `Comparison` with the delta per (metric, Field), `None` when a metric is on one side only, plus mean token and cost deltas per Case (#27). `Experiment.pricing` (set by `Runner(pricing=...)`) keeps the target's prices so `compare` can price each side; it is never applied to the Judge, and an Experiment with no recorded usage yields `None` token and cost deltas, not `0`. The usage deltas cover only the Cases both Experiments have; the others are listed in `Comparison.only_in_a` and `only_in_b`.
- New `Runner` (`assayer.runner`) that runs a target over a Dataset and returns an Experiment (#26): a plain return value is wrapped in one model Step, `repetitions=k` keeps each repetition as its own Trajectory, and Scores and evaluation failures land on the Experiment. `load_cases` loads a Dataset from a list or JSON and validates only the fields the chosen metrics `require`. The legacy pipelines are untouched.
- Public metric contract `Metric` (`level`, `requires`, deterministic or Judge-based), the `Registry` that holds built-in and custom metrics alike, and `step_efficiency` as the first metric on it (#25). A missing `requires` input emits no Score and an `EvaluationFailure`; the legacy registries stay until the clean break.
- Vendor-neutral models `Trajectory`, `Step`, `Score`, `Experiment`, `EvaluationFailure`, `Dataset` and `Case` beside the legacy ones (#24); `PricingConfig` moved to `assayer.models` and still importable from `assayer.runner.pricing`.
- `Experiment.total_judge_usage(pricing)` prices the Judge bucket. `TokenUsage` supports addition; `Score` requires `target_id` for step targets and rejects non-numeric values.
- Research notes under `docs/research/` on agent metrics, LLM/RAG metrics, Langfuse, LangSmith, OpenTelemetry/OpenInference and library packaging.
- `GLOSSARY.md` with the initial domain language: Trajectory, Score, Adapter and Judge.
- Domain terms Step, Dataset, Case, Experiment, Field, Alignment and End state in `GLOSSARY.md`, and ADR 0001 for the own Trajectory format.
- Harness template: agent skills, git hooks, CI, `.wiki/` knowledge bundle and `docs/agents/`.
- `Package organization` section in `CODE_STANDARDS.md`.
- Test job in CI and a `dev` dependency group with `pytest`.
